# Multica dcode ACP entry

Install the exact dependency snapshot in a private Python 3.13 venv, then install
this directory with `uv pip install --python <venv>/bin/python --no-deps
--no-build-isolation ./runtime-bridges/deepagents`. Select the resulting absolute
`multica-dcode-acp` executable with the `deepagents` protocol family. Do not pass
`--acp` yourself; the backend owns protocol/model/config arguments.

The entry delegates directly to `deepagents_code.main.cli_main`. Its only hook
wraps the dynamically imported `resolve_and_load_mcp_tools` in deepagents-code
0.1.68. It preserves arguments, tool identities and manager ownership on success;
failed required metadata triggers cleanup and a safe failure receipt. It does not
call tools for readiness, run another loader, or replace the agent loop.

`MULTICA_DEEPAGENTS_REQUEST` is generated by the Go backend for each process. Do
not configure it manually. The receipt is a lifecycle/compatibility contract, not
a defense against a malicious process running as the same OS user.

Unit tests (metadata fixtures, no model):

```sh
PYTHONPATH=runtime-bridges/deepagents <venv>/bin/python -m unittest discover -s runtime-bridges/deepagents/tests -v
```

The real loader/daemon test is excluded by default Go builds and requires both
`-tags=agentintegration` and `MULTICA_RUN_REAL_AGENT_SMOKE=1`, plus an absolute
`MULTICA_DEEPAGENTS_TEST_PYTHON`. `tests/real_entry.py` separately requires that
same environment gate and `MULTICA_DEEPAGENTS_TEST_ENTRY` pointing to the installed
console entry. It uses a temporary, credential-free environment and expects the
official CLI's missing-model-credentials failure, not a successful model turn.

See `docs/deepagents-runtime.md` for configuration, isolation and limitations.
